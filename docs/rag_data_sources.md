# RAG 레시피 데이터 출처 및 벡터 인덱스 구성

> [RAG-DATA] 시은 담당  
> 본 문서는 RAG 기반 레시피 추천 기능에 사용한 공공데이터의 출처,
> 이용 조건, 수집 규모와 임베딩 및 벡터 인덱스 구축 방식을 정리한다.

## 1. 개요

본 프로젝트의 RAG(Retrieval-Augmented Generation) 기반 레시피 추천 기능은
공공기관에서 제공하는 실제 레시피 데이터를 수집하여 로컬 레시피 코퍼스를 구축하고,
이를 임베딩한 FAISS 벡터 인덱스에서 사용자의 보유 재료와 관련성이 높은 레시피를 검색한 뒤
검색 결과를 LLM의 최종 레시피 생성 근거로 활용한다.

현재 레시피 코퍼스는 다음 두 공공데이터를 사용한다.

| 제공기관 | 데이터/API | 수집 건수 |
| --- | --- | ---: |
| 농촌진흥청 국립식량과학원 | 농식품 식단관리(메뉴젠) 음식 및 조리정보 | 91건 |
| 식품의약품안전처 식품안전나라 | 조리식품의 레시피 DB (COOKRCP01) | 1,155건 |
| **합계** |  | **1,246건** |

수집된 데이터는 다음 경로에 JSONL 형식으로 저장한다.

`data/recipe_corpus/recipes.jsonl`


## 2. 농촌진흥청 국립식량과학원 데이터

### 2.1 사용 데이터

- 제공기관: 농촌진흥청 국립식량과학원
- 데이터명: 농식품 식단관리(메뉴젠) 음식 및 조리정보
- 데이터 형식: XML Open API
- 주요 활용 필드:
  - 음식 코드(`fd_Code`)
  - 음식명(`fd_Nm`)
  - 조리법명(`ckry_Nm`)
  - 조리법 요약정보(`ckry_Sumry_Info`)
- 프로젝트 수집 건수: **91건**

API에서 조회된 데이터 중 조리법 정보가 없거나
`추후 정보를 갱신 예정`으로 표시된 데이터는
RAG 검색 품질을 위해 코퍼스에서 제외하였다.

현재 농촌진흥청 레시피 91건은 음식 및 조리정보 API를 기준으로 수집하였다.
별도의 음식 및 재료 정보 API 인증 문제가 발생한 시점에는
재료 목록을 실시간으로 추가 수집하지 않고 기존 조리정보를 유지하였다.
따라서 일부 농촌진흥청 레시피의 `ingredients` 필드는 빈 배열일 수 있다.


### 2.2 이용 조건

농촌진흥청 국립식량과학원의
`농식품 식단관리(메뉴젠) 음식 및 조리정보`는
공공누리 제4유형 조건으로 제공된다.

공공누리 제4유형의 주요 조건은 다음과 같다.

- 출처를 반드시 표시해야 한다.
- 상업적 목적으로 이용할 수 없다.
- 원 저작물을 변경하거나 2차적 저작물로 변형하여 이용할 수 없다.
- 프로젝트에서 해당 데이터를 사용할 때에는 원 데이터의 제공기관과 데이터명을 명확하게 표시한다.

따라서 본 프로젝트에서는 해당 데이터 자체를 상업적으로 판매하거나
원본 레시피를 임의로 수정한 데이터셋으로 재배포하지 않는다.


### 2.3 출처 표기 방법

농촌진흥청 데이터를 참고한 레시피의 출처는 다음과 같이 표기한다.

**권장 표기 예시**

`출처: 농촌진흥청 국립식량과학원, 농식품 식단관리(메뉴젠) 음식 및 조리정보`

RAG 응답에서는 검색에 실제 사용된 레시피명까지 포함해 다음 형식으로 표시한다.

`레시피명 - 농촌진흥청 국립식량과학원 농식품 식단관리(메뉴젠) - 공공데이터포털 원문 페이지`

예:

`돼지고기완자전 - 농촌진흥청 국립식량과학원 농식품 식단관리(메뉴젠) - 공공데이터포털 원문 페이지`


## 3. 식품안전나라 데이터

### 3.1 사용 데이터

- 제공기관: 식품의약품안전처
- 서비스: 식품안전나라 데이터활용서비스
- 데이터명: 조리식품의 레시피 DB
- 서비스 ID: `COOKRCP01`
- 데이터 형식: JSON Open API
- 주요 활용 필드:
  - 레시피명(`RCP_NM`)
  - 재료정보(`RCP_PARTS_DTLS`)
  - 만드는 법(`MANUAL01` ~ `MANUAL20`)
- 프로젝트 수집 건수: **1,155건**

해당 데이터에서 레시피명, 재료와 조리 단계를 추출하여
RAG에서 사용할 공통 레시피 구조로 정규화하였다.


### 3.2 이용 조건

식품안전나라의 `조리식품의 레시피 DB`는
출처표시를 조건으로 공개된 공공데이터이다.

공식 데이터활용서비스에 명시된 이용허락범위는 다음과 같다.

- 출처를 표시해야 한다.
- 상업적 이용과 비상업적 이용이 가능하다.
- 변형 및 2차적 저작물 작성이 가능하다.

따라서 본 프로젝트에서는 식품안전나라 데이터가 사용된 경우
식품의약품안전처와 식품안전나라 `조리식품의 레시피 DB`를
원 데이터 출처로 명시한다.


### 3.3 출처 표기 방법

**권장 표기 예시**

`출처: 식품의약품안전처 식품안전나라, 조리식품의 레시피 DB`

RAG 응답에서는 검색에 실제 사용된 레시피명과 함께 다음 형식으로 표시한다.

`레시피명 - 식품안전나라 조리식품의 레시피 DB - 식품안전나라 원문 페이지`

예:

`닭봉 로제스튜 - 식품안전나라 조리식품의 레시피 DB - 식품안전나라 원문 페이지`

최종 추천 레시피의 `sources` 필드에는
LLM이 실제 참고한 검색 문서의 레시피명과 출처만 포함한다.


## 4. 레시피 데이터 정규화

두 API의 서로 다른 응답 구조를 다음 공통 형식으로 정규화하였다.

```json
{
  "title": "레시피명",
  "ingredients": [
    "재료1",
    "재료2"
  ],
  "steps": [
    "조리 단계 1",
    "조리 단계 2"
  ],
  "source": {
    "api_name": "출처 API 이름",
    "url": "공식 출처 페이지"
  }
}

```

정규화된 레시피는 한 줄에 하나의 JSON 객체가 저장되는
JSONL 형식으로 관리한다.

최종 수집 결과는 다음과 같다.

- 농촌진흥청: **91건**
- 식품안전나라: **1,155건**
- 전체 레시피: **1,246건**


## 5. 청킹 방식

레시피 검색을 위해 각 레시피의 제목, 재료, 조리법을
하나의 검색용 텍스트로 변환하였다.

검색용 텍스트는 다음과 같은 구조를 가진다.

```text
레시피명: 콩자반
재료: 콩, 간장, 설탕, 물엿, 통깨
조리법:
1. 콩을 씻는다.
2. 간장과 설탕을 넣고 조린다.
3. 물엿과 통깨를 넣어 마무리한다.
```

긴 레시피가 하나의 임베딩에 지나치게 많은 정보를 포함하지 않도록
문자 단위 청킹을 적용하였다.

- 청크 크기: **700자**
- 청크 오버랩: **100자**
- 레시피 수: **1,246개**
- 최종 청크 수: **1,260개**

오버랩을 적용함으로써 청크 경계에 위치한 재료나 조리정보가
분리되면서 의미가 손실되는 문제를 완화하였다.


## 6. 임베딩 방식

텍스트 임베딩에는 Sentence Transformers 기반의
다국어 문장 임베딩 모델을 사용하였다.

- 모델: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
- 임베딩 차원: **384차원**
- 대상: 레시피 제목, 재료, 조리단계를 포함한 청크 텍스트
- 임베딩 벡터 수: **1,260개**

한국어 레시피 검색이 주요 목적이므로
한국어를 포함한 다국어 문장 의미 검색이 가능한 모델을 선택하였다.

임베딩 생성 시 `normalize_embeddings=True`를 적용하여
각 임베딩을 정규화하였다.


## 7. FAISS 벡터 인덱스

로컬 벡터 검색에는 FAISS를 사용한다.

인덱스 타입은 다음과 같다.

`IndexFlatIP`

임베딩 벡터를 정규화한 뒤 Inner Product 검색을 적용하여
코사인 유사도와 동일한 방식으로 관련 레시피를 검색한다.

전체 데이터 규모가 약 1천 건 수준으로 작기 때문에
별도의 근사 최근접 이웃 인덱스보다
모든 벡터를 직접 비교하는 `IndexFlatIP` 방식을 사용하였다.

생성된 인덱스 관련 파일은 다음 위치에 저장한다.

```text
data/recipe_corpus/index/
├── recipes.faiss
├── chunks.jsonl
└── config.json
```

각 파일의 역할은 다음과 같다.

- `recipes.faiss`
  - 1,260개의 레시피 청크 임베딩을 저장한 FAISS 인덱스
- `chunks.jsonl`
  - FAISS 벡터 번호와 실제 레시피 문서 및 메타데이터를 연결
- `config.json`
  - 임베딩 모델명, 임베딩 차원, 청크 크기, 청크 수 등의 설정 기록


## 8. RAG 검색 및 추천 흐름

사용자의 보유 재료는 다음 과정으로 처리된다.

```text
사용자의 보유 재료
        ↓
검색 질의 문자열 생성
        ↓
Sentence Transformer 임베딩
        ↓
FAISS IndexFlatIP 검색
        ↓
관련 레시피 Top-K 검색
        ↓
검색된 실제 레시피를 LLM 프롬프트의 근거 문서로 전달
        ↓
LLM 최종 추천 레시피 생성
        ↓
실제로 사용한 문서의 출처를 sources에 포함
```

기본 검색 개수는 Top-5이다.

동일한 재료 조합에 대한 반복 검색 비용을 줄이기 위해
RAG 서비스에서는 검색 결과를 메모리에 **60초간 캐싱**한다.

캐시 테스트에서는 최초 검색 시 임베딩 모델 및 인덱스 로딩을 포함하여
약 **7.415초**가 소요되었고,
동일한 재료 조합의 두 번째 검색은 캐시를 사용하여
약 **0.0초**로 단축되었다.


## 9. 장애 발생 시 처리

실제 사용자 추천 요청에서는 농촌진흥청이나 식품안전나라 API를
매번 호출하지 않는다.

공공 API는 코퍼스 구축 또는 갱신 단계에서만 사용하고,
실제 RAG 검색 시에는 이미 저장된 로컬 데이터를 사용한다.

```text
recipes.jsonl
        ↓
FAISS 로컬 인덱스
        ↓
RAG 검색
```

따라서 공공 API가 일시적으로 중단되더라도
기존에 구축한 코퍼스와 FAISS 인덱스가 존재하면
레시피 검색 및 추천 기능을 계속 사용할 수 있다.

FAISS 인덱스가 존재하지 않거나 손상되어 검색에 실패하는 경우에는
기존 `llm_recipe_service.py`의 직접 생성 방식으로 fallback한다.

fallback 시 검색 문서를 사용하지 않았으므로
`Recipe.sources`는 빈 배열(`[]`)을 유지한다.


## 10. 보고서용 요약

본 프로젝트는 농촌진흥청 국립식량과학원의 농식품 식단관리(메뉴젠)
음식 및 조리정보 91건과 식품의약품안전처 식품안전나라의
조리식품 레시피 DB 1,155건을 수집하여 총 1,246건의
레시피 코퍼스를 구축하였다.

수집 데이터는 레시피명, 재료, 조리단계 및 출처를 기준으로
공통 JSONL 형식으로 정규화하였다. 이후 레시피 텍스트를
700자 단위, 100자 오버랩으로 청킹하여 총 1,260개의 문서를 생성하였다.

각 청크는
`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
모델을 이용해 384차원 벡터로 임베딩하였으며,
정규화된 임베딩을 FAISS의 `IndexFlatIP` 인덱스에 저장하였다.

이를 통해 사용자의 보유 재료를 의미 기반으로 검색하고,
관련성이 높은 실제 레시피 Top-K를 LLM의 근거 문서로 제공하는
RAG 기반 추천 구조를 구현하였다.

최종 LLM 응답에는 실제 검색 및 생성에 참고한 레시피의
이름과 공공데이터 출처를 `sources` 필드에 명시하여
추천 결과의 근거와 데이터 출처를 확인할 수 있도록 하였다.
