## 1. 배경

현재 `model/artifacts/class_names.json`에는 6종의 클래스만 등록되어 있다.

```json
["potato", "carrot", "cabbage", "tomato", "eggplant", "paprika"]
```

여기에 신규 13종을 추가해 총 19종 분류 모델로 확장한다.

**수량 기준**
- 클래스당 **최소 200장, 권장 300장** (학습/검증/테스트 분리 후에도 클래스당 최소 150장 이상 학습셋 확보 목표)
- 라벨/캔/포장지 등 텍스트·브랜드가 두드러지는 품목(돼지고기, 참치캔, 김치)은 특정 브랜드에 과적합되지 않도록 최소 250장 이상, 브랜드·포장 다양성 확보
- 기존 6종은 기존 데이터셋을 그대로 재사용하되, 클래스당 200장 미만인 경우 동일 기준으로 보강

**공통 촬영/수집 가이드(제안)**
- 다양한 조명(자연광/실내광), 배경(도마/식탁/봉지), 각도(정면/위)에서 촬영
- 클래스당 최소 2곳 이상 출처(직접 촬영 + 공개 데이터셋/크롤링) 혼합 권장
- 학습:검증:테스트 = 대략 70:15:15 비율 분할

## 3. 배포 플랫폼 비교 (무료/저비용 티어 기준)

> 코드/설정 작업은 아직 진행하지 않음. 아래는 의사결정을 위한 비교 자료.

| 항목 | Render | Railway | Fly.io |
|---|---|---|---|
| 무료 티어 | Free Web Service 제공(단, 일정 시간 미사용 시 sleep, 월 750시간 한도) | 과거 무료 크레딧 제공했으나 현재는 매월 소액 크레딧(Trial/Hobby, 사용량 기반) 위주로 축소됨 | 무료 티어 폐지, 소규모 앱은 저비용(약 $5 내외/월)으로 운영 가능한 pay-as-you-go 구조 |
| Cold start / Sleep | Free 플랜은 15분 미사용 시 슬립 → 재요청 시 수십 초 지연 | Hobby 플랜은 상시 구동 가능(과금 발생), 무료 크레딧 소진 시 서비스 중단 | 기본적으로 상시 구동(머신 정지 옵션 선택 가능), 저지연 |
| 배포 방식 | GitHub 연동, Dockerfile 또는 자동 빌드(Node/Python 등) 지원 | GitHub 연동, Dockerfile 또는 Nixpacks 자동 빌드 | `flyctl` CLI + Dockerfile 기반, GitHub Actions 연동 가능 |
| 모델 파일(수십~수백MB .keras) 배포 적합성 | Free 플랜 디스크/메모리 제한 있음(512MB RAM), 큰 모델은 저사양에서 느릴 수 있음 | 무료 크레딧 한도 내에서만 가능, 리소스 조절 유연 | 메모리/CPU를 유료로 유연하게 조절 가능, 모델 서빙에 적합한 편 |
| 예상 월 비용(소규모 트래픽 기준) | $0 (Free, sleep 감수) ~ $7(Starter) | 무료 크레딧 소진 후 사용량 과금(예상 $5~10) | 소규모 인스턴스 기준 약 $0~5(무료 크레딧+저사양 머신) |
| 장점 | 설정 간단, 무료로 시작하기 쉬움 | Postgres 등 부가 서비스 연동 간편 | 글로벌 리전 선택, 컨테이너 제어 자유도 높음, 상시 구동에 유리 |
| 단점 | Free 플랜 슬립으로 인한 응답 지연(모델 추론 API에 불리) | 무료 크레딧이 제한적이라 사실상 유료 전제 | 초기 설정(flyctl, Dockerfile) 난이도가 상대적으로 높음 |

**초기 검토 의견(안)**
- 프로토타입/데모 단계: **Render Free**로 우선 배포해 무료로 검증 (단, 모델 추론 API는 슬립으로 인한 첫 요청 지연을 감안)
- 실사용/시연 안정성이 중요해지는 시점: **Fly.io** 저비용 유료 플랜으로 전환해 상시 구동 확보
- 팀 내 Postgres 등 DB를 함께 쓸 계획이 있다면 **Railway**도 후보로 유지

*(실제 배포 코드/설정 작업은 이번 문서 작성 범위에 포함하지 않으며, 플랫폼 선정 후 별도 작업으로 진행 예정)*
